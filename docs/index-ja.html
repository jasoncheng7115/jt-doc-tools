外部のオンラインサービスにアップロードせずに文書を処理

ネット上には「無料」の PDF / 画像 / Office 処理ツールがたくさんあります：フォーム入力、押印、結合、圧縮、署名、暗号化…
数クリックで手軽ですが、あなたのファイルは他人のサーバーにアップロードされます。契約書、人事、財務、顧客情報、身分証、銀行口座を、外部のサービスに預けてよいでしょうか？

オンライン PDF ツールの不安
  • ファイルが第三者のサーバーにアップロードされ、いつ本当に削除されたのか確認できません
  • 多くはソースコードが公開されておらず、サーバー側でデータがどう扱われているかわかりません
  • 無料版にはプライバシーポリシーの変更や、あなたのファイルで AI を学習させる条項がよくあります
  • 身分証 / 銀行口座 / 顧客リスト / 契約書のアップロード = 個人情報保護法 / GDPR のリスク
  • 社内ネットワークの監査から見えず、SIEM も受け取れないため、コンプライアンスを追跡できません
  • 国や拠点をまたぐ転送がデータの越境という懸念を招きます
ローカルでの自前構築 + オープンソースなら安心できます
  • ファイルは決してあなたのサーバーから出ません —— 第三者 API も telemetry もありません
  • ソースコードが公開されています（AGPL-3.0）—— 監査したいものはすべて確認できます
  • 監査記録はあなたの SQLite に書き込まれ、社内の SIEM へリアルタイムに転送できます
  • ロールと権限マトリクス：誰がどのツールを使えるかを会社が管理できます
  • 個人情報保護法 / GDPR への対応：データは自社のサーバールーム / 社内ネットワークに残ります
  • ワンライナーでインストールでき、既存の Linux / macOS / Windows で動くため、ライセンス費用を節約できます
中核機能

51 のツール、5 つのカテゴリ

どのツールにも専用のページがあり、左のサイドバーからワンクリックで切り替えられます。処理結果はすべて PDF または画像でダウンロードできます。

用語について：本サイトでいう文書ファイルは .docx / .odt、表計算は .xlsx / .ods、プレゼンテーションは .pptx / .odp、PDF は .pdf を指します。オフィス文書はこの 4 分類の総称 —— ツールが複数の形式を同時に受け付けられるときにこう呼びます。
Office エンジンが必要なツールにはレンチのアイコンが付きます。これらのツールは Word / Excel / PowerPoint / ODF を扱うときに OxOffice または LibreOfficeを使います（OxOffice を優先します。OSSII が維持する台湾ローカライズ版の fork で、CJK のサポートがより充実しています）。残りの 28 個のツールは PDF / プレーンテキスト / 画像のみを扱うため、Office エンジンは不要です。インストールスクリプトが OxOffice を自動で検出 / 追加インストールします。

  • 押印と署名印章 / 署名 / ロゴを適用します。一括処理と位置の微調整にも対応します

  • 割印1 つの印章を数片に切って連続したページにまたがって押すことで、差し替えやページ抜けが一目でわかります。またがるページ数、位置、角度をすべて設定できます（文書ファイルの入力にはエンジンが必要です）

  • スキャン補正傾いて撮影・傾いてスキャンされた文書の黒い縁を切り落とし、傾きを直し、むらのある下地をならします。スマートフォンでの撮影では紙の四隅を検出して透視補正し、ページごとに補正角度と残りの傾きを報告します。PDF、画像、文書ファイルを受け付けます（文書ファイルの入力にはエンジンが必要です）

  • 注釈のフラット化注釈をページの内容に焼き込み、受取側が削除できないようにします。フォーム項目は入力可能なまま残します

v1.11 の新機能

マイワークスペース：ツール間でのファイルの一時保存と取り出し

どのツールで生成した PDF / PNG もワンクリックでサーバーに保存でき、本人のアカウントからだけ見えます。どのツールのアップロード欄からもワンクリックで取り出して再利用できるため、ファイルを探し直したりアップロードし直したりする必要がありません。管理者は機能のオン/オフと、容量・保持期間の一元管理ができます。

ワークスペースに保存

各ツールが出力した PDF / PNG をワンクリックでサーバーに残し、アカウント単位で分離して本人だけが見られます。「マイワークスペース」ページで直接ドラッグしてアップロードしたり、トップページでサムネイルを確認したり、一括削除したりもできます。

ワークスペースから読み込む

どのツールのアップロード欄からもワンクリックで取り出せるため、ツールをまたいだ受け渡し（OCR → 押印 → 匿名化 …）で、同じファイルをツール間でダウンロードし直してアップロードし直す必要がありません。

管理者による制御

機能全体のオン/オフ（無効にすると完全に非表示）、1 人あたりの容量、1 ファイルの上限、保持時間を一元的に設定でき、ユーザーの使用分を空にすることもできます。認証が無効のときは、スタンドアロンの共用ワークスペースになります。

v1.14 の新機能

バックグラウンドジョブと完了通知：送信後はページを閉じてもよく、完了時に通知

変換、OCR、一文ずつ翻訳のような時間のかかる作業はサーバーに任せられるため、進捗バーを見張る必要がありません。完了するとこちらから通知し、結果は自動的に「マイワークスペース」に残ります。管理者側からはサイト全体のキューとリソース使用量が見え、すべての並列上限も変更できます。

31 のツールがバックグラウンドジョブで動きます

PDF → 文書ファイル / プレゼンテーション、OCR 文字認識、一文ずつ翻訳、圧縮、結合、透かし、押印…送信後はそのままタブを閉じてかまいません。「マイジョブ」ページで進捗、キューの順番、経過時間を確認でき、途中でキャンセルもできます。出力が単一ファイルでないツール（一文ずつ翻訳など）では、戻ると元のページに復帰して続きを確認できます。

完了したらこちらから通知

サイト内通知に未読数を表示します。Email では、サイトのロゴとツールのアイコンを含む通知メールを送ります。ほかに Telegram / Slack / Teams / Discord / LINE / Webhook など 8 種類のチャネルにも接続できます（現時点では開発段階で、実際のサービスでの検証はまだ行っていません）。メッセージにはツール名、ファイル名、状態のみを含み、ファイルの内容は含みません。

web の応答が常に優先

変換プロセスは優先度を下げ、使えるコア数も制限します（既定で web 用に 1 つ確保）。そのため大きなファイルの変換中でも画面は固まりません —— 変換自体が少し遅くなるだけです。ディスパッチの前にメモリを見積もり、足りなければキューで順番待ちさせ、無理に開始してマシンを落とすことはありません。ジョブの状態はデータベースに保存されるため、サービスを再起動しても消えません。

優先的な処理（割り込み）

管理者は少数のユーザーを指定できます —— 経営層や、期限のある重要な作業です。その人たちが送信したジョブはキューの先頭に入り、次にディスパッチされるのはそのジョブになります。実行中のジョブは中断しません（変換の途中で強制終了しても中途半端な成果物しか残りません）。効果は「今すぐ交代」ではなく「次はあなた」です。リストの中では互いに先着順のままで、メモリが足りないときは同じく順番待ちになります。

管理者にはすべてが見えます

サイト全体のジョブ一覧：誰が送信したか、どのツールか、どのファイルか、何番目か、何分動いているかを確認でき、進行中のみの表示や、1 件ずつのキャンセルもできます。メンテナンス前にはディスパッチを一時停止して、実行中のものは終わらせつつ新しいものは開始しないようにできます（実行中の変換は独立した子プロセスのため凍結できません —— 画面にはそのとおり説明し、押せば止まると誤解させません）。

性能が見え、上限も変更できます

実行中 / 順番待ちの件数、Office 変換の占有、CPU とメモリの使用量が同じページにまとまっており、クリックすると履歴の推移グラフを表示します。メモリは子プロセスを実測した数字です（実際にメモリを使うのは soffice です）。5 つの並列上限はすべて変更でき、しかも大きく入力しても実際に使えるメモリで頭打ちになります。

v1.14 の新機能

AD / LDAP ディレクトリ連携：ドメインコントローラーの冗長化とアカウントの一元管理

ディレクトリサービスと連携したあと、実際によく起きる問題には次のようなものがあります：主要ドメインコントローラーの再起動、主要グループに設定した権限が有効にならない、退職者のアカウントが使えるまま残る、アカウントが他人に使われる。以下の仕組みでそれぞれに対応します。

複数のドメインコントローラーによる冗長化

サーバーのアドレスは複数台入力でき（カンマまたは改行区切り）、順に試します —— 主要 DC のメンテナンスや再起動のときは自動で次の 1 台に切り替わるため、全社員がログインできなくなることはありません。接続にも照会にもタイムアウトがあり、DC につながらないときは数秒以内に明確なメッセージを返すので、ユーザーがシステム障害と思い込むまで待たされることもありません。停止していた DC は復旧すると自動的にローテーションに戻ります。

AD の主要グループも有効

AD の主要グループ（primaryGroupID）は memberOf に現れません —— これは AD 連携で最も踏みやすい落とし穴です。ある部署を主要グループに設定して権限を付けると、メンバーが誰も権限を受け取れず、しかも AD ユーザーの「所属するグループ」タブでもまったく原因がわかりません。現在は主要グループも自動的に権限の解決に含めます。OpenLDAP にはこの概念がないため、動作はまったく変わりません。

退職 / 無効化されたアカウントが見えます

ディレクトリ同期はもともと増えるだけでした：AD 側で人を無効化したり削除したりしても、本サイトのアカウント、ロールの割り当て、グループ所属はすべて残り、「このシステムに今誰がいるのか」に答えられませんでした。現在はユーザー一覧に「ディレクトリに存在しません」と「AD 側で無効」の 2 つのビューとバッジがあります。判定は完全スキャンのみを根拠とします —— 名称の絞り込み付きの同期ではディレクトリの一部しか見えず、それを基準にすると組織全体を退職扱いにしてしまうためです。

一括での無効化と、その安全弁

「ディレクトリに存在しません」は数百人、十数ページに及ぶこともあります —— ワンクリックですべて無効化でき、押す前に試算して実際に何人に影響するかを表示します。同期後に自動で無効化する設定もできます（既定は無効）。重要なのは安全弁です：一度に変更する人数がディレクトリのアカウント総数の 20% を超えると、バッチ全体を中止し、1 人も変更しません —— サービスアカウントのパスワード期限切れや検索範囲の変更で「全社員が消えた」ように見えることがあり、そのときは何もしないのが正解だからです。しかも無効化するだけで削除はしません。アカウントも権限の割り当ても残るため、本人が戻ってきたらワンクリックで復元できます。

今、誰がログインしているか

ユーザー一覧にオンライン人数をそのまま表示します（同じ人がブラウザーを 3 つ開いていても 1 人と数えます）。アカウントごとに現在のログイン端末（ブラウザーと OS、送信元アドレス、最終アクティビティ時刻）を確認でき、個別または一括で強制ログアウトできます。操作は監査記録に残ります。アカウント漏えいが疑われるときは、パスワードを変更しなくてもまずすべての端末を切断できます。

権限の割り当てに、相手のログインを待つ必要はありません

ディレクトリの参照からどのユーザーをクリックしてもそのままロールを割り当てられます。一度ログインしてもらう必要はないため、新入社員は初日から使えます。「所属グループ」の各行からも、その場でグループ権限を設定できます。従来は OU 全体にしか割り当てられませんでしたが、「この OU の中で財務はこの 2 人だけ」というのが実務では最もよくある要件です。

「結局この人は何が使えるのか」が一目でわかります

権限の出どころは 4 か所に散らばっており（直接割り当てたロール、入れ子の上位グループを含むグループ、OU、ツールの直接付与）、何かあったときに説明が困難でした。ユーザーの編集時に実効権限パネルを開くと、その人が最終的にどのツールを使えるのか、どの項目がどのルール由来かまで表示します。監査への回答や引き継ぎの説明にそのまま使えます。

パスワードの期限切れを先に把握できます

パスワードの期限切れは、ユーザーから見ると「急にログインできなくなった」という症状で、そのあとで管理者に問い合わせが来ます。現在は一覧にあと何日で期限切れかを表示します（期限切れは別途表示）ので、事前に知らせられます。日付はAD 自身が計算した値を読んでいるため、細かなパスワードポリシー（PSO）が適用されている人や「パスワードを無期限にする」を設定している人でも正確です —— ドメインの全体設定から自分で推定すると誤った値になります。

AI 付加機能（任意）

14 のツールが LLM AI による機能強化に対応

自前の LLM（ローカルの Ollama、LiteLLM などの LLM ゲートウェイ、vLLM、LM Studio、DGX Spark など）を接続すると、この 14 個のツールでスマートな機能が使えます。コアツールは LLM にまったく依存しません。設定しなくても 100% 使えます。

text

一文ずつ翻訳

文に分けて LLM に送って翻訳し、左に原文・右に訳文を並べて表示します。文ごとに個別で翻訳し直せます。台湾繁体字の IT 用語表を内蔵し、「文書の分野」ヒント（法律 / 医療 / 技術）を任意で指定すると専門用語がより正確になります。

効果：契約書 / 論文のような長文でも、一文ずつ並列で翻訳するため手作業より速くなります

text

文書の翻訳（オフィス文書全体）

Word / Excel / PowerPoint 全体を別の言語に翻訳し、同じ形式・同じレイアウトのファイルを出力します —— テキストだけを置き換え、枠線 / 表 / ヘッダーフッター / 画像はそのままの位置に残ります。段落を単位として LLM に送り、翻訳後は先頭 6 ページの「左が原文、右が訳文」の並列プレビューが付きます。

効果：契約書 / 規程の文書をそのまま訳済みのファイルとして出力でき、レイアウトを組み直す必要がありません

text

テキスト抽出（段落の再構成）

PyMuPDF で抽出したあと、段落ごとに LLM へ送り、改行で分断された文を自然な段落へつなぎ直します。TXT / Markdown / DOCX / ODT として出力します。

効果：PDF のレイアウトで分断された本文が、読んでいて引っかからなくなります

vision

フォームの自動入力（検証）

入力後、LLM が各項目のレンダリング結果（PNG）を自動でレビューし、項目のずれ / 見切れ / チェックボックスの付け間違いを検出します。

効果：30 項目の取引先フォームでも、1 項目ずつ目視する必要がなく、LLM が指摘した数項目だけを確認すれば済みます

text

文書の匿名化（追加検出）

正規表現は形式の決まったもの（マイナンバー / 電話番号 / 銀行口座 / 統一番号）を拾い、LLM が「顧客コード A-2024-0815」「上司の王課長」のような文脈依存のケースを追加で拾います。

効果：正規表現では拾えない非標準の形式や、文脈に依存する項目を LLM が補います

text

テキストの匿名化（追加検出）

上と同じですが、プレーンテキストの入力を受け付けます。カスタマーサポートの会話 / log / Email の内容に向いています。貼り付けても .txt / .md をアップロードしても構いません。

効果：プレーンテキストの場面でも、同じ正規表現 + LLM の二重検出を使えます

text

文字数の集計（要約 / キーワード）

文字数を集計したあと、LLM に内容の要約と重要概念の一覧を生成させます（任意の機能で、既定は無効です）。

効果：初めて読む長文でも、まず LLM の要約で主旨をつかんでから精読するか決められます

text

会議の要約

会議の文字起こしから要約・決定事項・タスク・リスク・章立てを作ります。各項目に発言番号が付いており、クリックすると元の発言に戻れます。議事録は「何が決まったか」の根拠として使われるため、出典のない決定事項はその項目がないよりも悪いからです。

効果：2 時間の会議でも、決定事項とタスクが 1 件ずつ並び、それぞれ誰がどの箇所で言ったのかを確認できます

text

公文書の起案（簽・函・簽辦意見）

普段の言葉の依頼を「簽」「函」に整え、来文から「簽辦意見」を起案します。企業から機関への公文にも使えます。金額・日付・法令・文書番号は入力内容と照合し、根拠が見つからないものに印を付けます。

効果：段落名・項番・結びを自分で整える必要がなく、担当者は中身と照合で指摘された箇所だけを確認すれば済みます

text

注釈の整理（自動グループ分け）

PDF 内のすべての annotation を抽出し、LLM が「注釈の内容のテーマ」で動的にグループ分けします（例：文章の修正が必要 / 書式の問題 / 疑問点の確認 / 確認済み など。LLM が自由に判断します）。

効果：複数人でレビューした長い文書で、同じ性質の修正提案をワンクリックでまとめられます

text

文書の差分比較（変更点の要約）

2 つの文書の行単位の diff のあとで、LLM が「全体として主に何が変わったか」を 3-5 文で説明します（任意で、既定は無効です）。

効果：契約書 / 草案 / 仕様の改訂後、まず LLM の要約を見てから逐条で精読するか決められます

text

OCR 文字認識（typo の補正）

EasyOCR / Tesseract の実行後、LLM が前後の文脈と照らして OCR のよくある誤字を補正します（例：「己」を「巳」と誤認識）。ハルシネーション対策を内蔵し、前後の word count が完全に一致するときにのみ適用するため、LLM が自由に書き換えることはありません。

効果：スキャン文書の OCR 結果がより整い、そのまま検索 / 編集に使えます

text + vision

送付前チェック（意味 + ビジュアルの検証）

構造チェック（ページサイズ / フォントの埋め込み）のあとで、LLM が内容の意味をチェックし（必須項目が実際に埋まっているか、記述に前後矛盾がないか）、vision モデルで PNG のビジュアル検証を行います（押印が文字にかぶっていないか、ページのレイアウトが崩れていないか）。

効果：正規表現 / 構造チェックでは拾えない「字面は合っているが意味が誤り」「見た目に問題がある」ケースを補えます

text

電子請求書の処理（勘定科目の判定）

請求書を読み取ったあと、売り手の統一番号 + 会社名 + 業種にもとづき、まとめて LLM に送って勘定科目（燃料費 / 会議費 / 通信費 など）を判定します。まず組み込みルールを通し、ルールで拾えなかったものを LLM が補います。ユーザーのカスタムルールで上書きすることもできます。

効果：経費精算の前に自動で分類でき、1 件ずつ科目を選ぶ手間がなくなります

導入の選択肢

  • ローカルの Ollama · 個人 / 小規模チームのお試し。コンシューマー向け GPU で gemma3:4b が動きます
  • DGX Spark / ワークステーション · 社内の単一 LLM サーバー。gemma4:26b を実行します（既定。ビジョンもテキストも可）
  • LiteLLM などの LLM ゲートウェイ / vLLM / SGLang / llama.cpp / LM Studio / jan.ai · OpenAI 互換のバックエンドならどれでも。モデルの「思考」は自動でオフにします

既定は無効です。/admin/llm-settings で有効にすると SSRF 対策が働きます（URL の allowlist + クラウドの metadata ホストの blocklist）。社内 LAN の IP は許可されますが、クラウドの metadata IP は拒否されます。詳しくは次をご覧ください LLM.md。

音声サービス連携 / 任意（v1.15.94）

会議録音の文字起こしと議事録の作成

録音は JTLW （jt-live-whisper、社内ネットワークに自前で立てられます）へ渡して認識と発言者分離を行います。 要約・決定事項・タスク・マインドマップ・翻訳はすべて本システムに残ります。 重要な録音がネットワークの外へ出ることはありません。

1

一度だけ設定

管理画面で送信先アドレスと API キーを入力します。自己署名証明書の場合は、証明書を貼り付けるだけです。検証は無効にしないでください。設定が済むまで、このツールはグレーアウトのままです。

2

録音をアップロード

音声でも動画でも受け付けます。変換が終わったらワンクリックで「会議要約」へ渡せます。API 経由で他のシステムから利用することもできます。

3

聞きながら読む

文字起こしにはタイムスタンプと発言者が付きます。波形をクリックすればその位置から再生され、再生中の行がハイライトされ、 発言者の記号をクリックすれば名前に変更できます。

2 つのシステムのつながり

JTDT はアカウント、権限、ファイル、結果画面を担当し、JTLW は音声を文字にすることだけを担当します。録音は有効期限の短い URL で渡し、文字起こしを本システムに保存したら、JTLW 側のコピーは削除できます。

企業向けの管理機能

単なるツールボックスではなく、管理できるプラットフォームです

認証を有効にすると、企業環境に欠かせない管理機能が一通りそろいます（すべてオープンソースで、有料版との差はありません）。

A

複数レルムの認証

ローカルアカウント / LDAP / Active Directory に同時対応します。同名のアカウントを別のレルムに併存させられ（jason@local + jason@ldap）、ログイン時にプルダウンで提供元を選びます。LDAP 設定には「サーバー接続をテスト」+「アカウントのログインをテスト」ボタンがあり、設定が正しいかワンクリックで検証できます。

B

SSO シングルサインオン

OIDC + SAML に対応し、Microsoft 365 / Entra ID、Google Workspace、Keycloak、Okta、Authentik などに接続できます。ローカル / LDAP / AD と併存し（ローカルの break-glass アカウントを残せます）、初回ログインでアカウントを自動作成し、IdP のグループをロールに対応付け、シングルログアウト（SLO）にも対応します。

C

Reverse Proxy SSO

Kerberos / SPNEGO：AD ドメインに参加し Windows にログイン済みのユーザーは、フロントの Nginx で認証したうえで自動ログインでき、アカウントとパスワードの再入力が不要です。ドメイン外のパソコンは引き続きログインページで別の方法を使います。既存の LDAP / AD 照会 + ロール / 監査 / 2FA をそのまま使い、「信頼するリバースプロキシ IP + ヘッダーの上書き」で偽造を防ぎます。reverse_proxy_sso.md をご覧ください。

D

ロールと権限

7 つの組み込みロール：管理者、監査役、一般ユーザー、文書管理、財務、営業、法務セキュリティ。新しいロールを自由に作成でき、ツールの利用権限をユーザー / グループ / OU に割り当てられます。in-memory cache により、権限の照会が性能に影響しません。

E

監査記録

ログイン / ログアウト / 失敗によるロック / 権限の変更 / 設定の変更 / アップロードのファイル名を含むツールの呼び出しをすべて記録します。SQLite （WAL） への非同期書き込みのため、サービスの性能には影響しません。絞り込みや CSV エクスポートができ、既定では 90 日保持したあと自動で削除します。

F

ログ転送

3 つの形式に対応します：syslog （RFC 5424 UDP/TCP）、CEF （ArcSight）、GELF （Graylog）。複数の宛先へ同時に送信でき、失敗した場合は 3 回再試行してからローカルの監査イベントへ降格します。Splunk / Graylog / ArcSight / SIEM に接続できます。

G

アップロードしたファイルの記録

独立した「アップロードしたファイルの記録」設定ページに、ツール経由でアップロードされたすべてのファイルを一覧表示します —— 誰が、いつ、どのツールで、どのファイル名を、どれだけの大きさで、HTTP の状態は何だったか。完全に追跡できます。

H

ファイルの保持 / クリーンアップ

フォーム入力 / 押印と署名 / 透かしの履歴 / 一時アップロード / Job の結果 / 監査について、分類ごとに保持日数を設定でき、スケジュールでクリーンアップします（起動時 + 6 時間ごと）。「無期限に保持」（-1）も設定できます。

I

設定のバックアップ / インポート

コンプライアンス / 職責分離（v1.5.0）

監査員ロールと二要素認証の必須化：職務分離によるコンプライアンス対応

認証を有効にすると、システムが jtdt-admin と jtdt-auditor の 2 つの組み込みアカウントを自動で作成します。それぞれ別のロールに属し、「システムを管理する人」と「記録を見る人」を完全に分離するため、ISO 27001:2022 などのコンプライアンス要件に適合します。

なぜ 2 つに分けるのか

コンプライアンス要件は「システムを管理する人」と「記録を見る人」の職責分離を求めます —— admin がユーザーの実際にアップロードしたファイルの内容をのぞくべきではなく、監査役がシステム設定を変更すべきでもありません。どちらの側も完全なアクセス権を持たない、これが separation of duties です。

TOTP 2FA の必須化

監査役ロールは初回ログイン時に /2fa-verify へ誘導され、自動でセットアップします（QR コードを表示）→ Google Authenticator / Microsoft Authenticator / Authy / 1Password のいずれかで読み取り → 6 桁を入力して完了します。監査役は自分で 2FA を無効にできず、admin も監査役ロールのユーザーの必須化を解除できません。

複数の監査役に対応

組み込みの jtdt-auditor のほかに、admin は sudo jtdt audit-user create <name> で監査役を何人でも追加できます（大企業で IT / 法務 / 内部監査が分担して確認する場合に向いています）。監査役ごとに独立した 2FA を持ちます。

監査役自身の行動も記録されます

監査役が閲覧するたびに auditor_view の audit event を 1 件記録します（path / method / IP）。admin は監査役が何を見たか確認できますが、監査役自身はそれを削除できません（UI に削除のエンドポイントがなく、そもそも読み取り専用です）。

すべての user が 2FA を使えます

監査役だけではありません —— どの user（LDAP / AD アカウントを含む）も「マイアカウント」のモーダルからセルフサービスで TOTP 2FA を有効にできます。有効にしたあとはいつでも無効にできます（auditor ロールを除く）。

緊急復旧の CLI

admin はオフラインで復旧できます：jtdt auth show / disable / set-local、jtdt reset-password <user>、jtdt audit-user create。パスワードを忘れた場合や LDAP の設定を誤った場合でも、再インストールは不要で、データも失われません。

データ保護とコンプライアンス

文書がどこに残るか、どんな場合に外部へ接続するか、ツール自体が備える管理策と組織が行うことをまとめ、台湾の個人資料保護法、GDPR、ISO/IEC 27001:2022 と ISO/IEC 42001:2023 の箇条・管理策と対応づけています。

データ保護とコンプライアンスを見る

クラウドに出さず、データは自分の手元に残ります

ファイルの処理はすべてあなたのサーバー上だけで行われます。
Linux にサイトを立てて社内ネットワークの複数人で使うことも、スタンドアロンでローカルに使うこともでき、クラウドサービスには一切アップロードしません。

クラウドに出さない

ファイルがサーバーの外に出ることはありません。外部 API の呼び出しも、外部の解析も、利用統計の送信もありません。

データディレクトリを分離

すべてのデータはシステムのデータディレクトリ（data/）にまとまり、ユーザーの個人ファイルとは混ざりません。バックアップはこの 1 か所だけで済みます。

監査ログを転送可能

認証を有効にすると、重要な操作はすべて記録され、社内の SIEM へリアルタイムに転送してコンプライアンス監査に使えます。

AI 機能はオプション

社内の LLM（Ollama など）を接続すると、翻訳・要約・フォームの検証などに AI 機能が加わります。既定ではオフで、接続しなくてもすべて使えます。

オープンソースで 1 行ずつ監査可能

AGPL-3.0 ライセンスで、ソースコードは GitHub で公開しています。お客様、内部監査、セキュリティコンサルタントが 1 行ずつ確認でき、難読化したバイナリや非公開のコンポーネントはありません。

セキュリティ指針に準拠

OWASP Top 10（2025）の各項目に対応する自動テストがあります（SECURITY.md）。セキュリティヘッダー、scrypt によるパスワードハッシュ、二要素認証を備え、脆弱性スキャンを毎週自動で行います。

導入前の注意事項
  • 社内ネットワークか VPN 経由でのみ使ってください。契約書、見積書、個人情報などの機密文書を扱います。インターネットに公開すると誰でもログインやファイルのアップロードを試せますが、社内ネットワークなら接続できるのは社員だけで、しかも先にログインが必要です。
  • 同じマシンで 1 人だけで使う場合を除き、リバースプロキシの後ろに置いてください。アプリは既定で 127.0.0.1:8765（HTTP のみ）だけで待ち受けます。複数人や他のコンピューターから使うときは nginx や Caddy などのリバースプロキシで HTTPS を提供し、:8765 をネットワークへ直接公開しないでください。
  • どうしても外部に公開する場合は自己責任です。少なくとも認証と二要素認証の必須化、WAF またはレート制限を加え、依存パッケージを常に更新してください。各種リバースプロキシの設定例は OPS.md のリバースプロキシの章を参照してください。
