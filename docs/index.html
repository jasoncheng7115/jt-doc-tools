為什麼要自架？

文件處理不必上傳到外部線上服務

網路上有很多「免費」的 PDF / 圖片 / Office 處理工具：表單填寫、用印、合併、壓縮、簽章、加密…
點兩下很方便，但你的檔案上傳到別人的伺服器。合約、人事、財務、客戶資料、身分證、銀行帳號，都適合交給外部服務嗎？

線上 PDF 工具的隱憂
  • 檔案上傳到第三方伺服器，無法確認何時真的被刪除
  • 多數沒公開原始碼，不知道伺服器端怎麼處理你的資料
  • 免費版常常有隱私政策變更、用你的檔案訓練 AI 的條款
  • 身分證 / 銀行帳號 / 客戶名單 / 合約上傳 = 個資法 / GDPR 風險
  • 公司網路稽核看不到、SIEM 收不到，合規無法追溯
  • 跨國 / 跨機房傳輸觸發資料跨境疑慮
地端自架 + 開源 才能安心
  • 檔案永遠不離開你的伺服器 — 沒有第三方 API、沒有 telemetry
  • 原始碼公開（AGPL-3.0）— 想稽核什麼都看得到
  • 稽核記錄寫在你的 SQLite，可即時轉發到內部 SIEM
  • 角色與權限矩陣：誰能用哪個工具，公司能控管
  • 個資法 / GDPR 合規：資料留在自己機房 / 內網
  • 一行指令安裝，跑在公司既有 Linux / macOS / Windows，省授權費

v1.11 新功能

我的工作區：跨工具暫存與取用檔案

在任何工具產出的 PDF / PNG 一鍵存進伺服器、只有自己的帳號看得到；任何工具的上傳區一鍵取回再用，免來回找檔、重新上傳。管理員可開關並統一控管容量與保留時間。

存至工作區

各工具輸出的 PDF / PNG 一鍵保留在伺服器，綁帳號隔離，只有自己看得到。也能在「我的工作區」頁直接拖曳上傳、首頁縮圖預覽、批次刪除。

從工作區載入

任何工具的上傳區一鍵取回，跨工具接力（OCR → 蓋章 → 去識別化 …），不必把同一份檔案在工具之間來回下載再上傳。

管理員控管

可開關整個功能（停用即完全隱藏）、統一設定每人容量額度、單檔上限與保留時數，並可清空使用者佔用。認證關閉時為單機共用工作區。

v1.14 新功能

背景作業與完成通知：送出後可關閉頁面，完成時通知

轉檔、OCR、逐句翻譯這類耗時的工作交給伺服器跑，不必守著進度條。做完了主動通知你，結果自動留在「我的工作區」。管理員這一側看得到全站佇列與資源用量，也調得動所有併行上限。

31 個工具走背景作業

PDF 轉文書檔 / 轉簡報檔、OCR 文字辨識、逐句翻譯、壓縮、合併、浮水印、用印…送出後可以直接關掉分頁。「我的作業」頁看得到進度、佇列位置與已過時間，跑一半也能取消。產出不是單一檔案的工具（例如逐句翻譯）點回去會接回原本的頁面繼續看。

做完主動通知

站內通知顯示未讀數；Email 寄出含站台 logo 與工具圖示的通知信。另可接 Telegram / Slack / Teams / Discord / LINE / Webhook 等 8 種管道（目前標示為開發階段，尚未接真實服務驗證）。訊息只含工具名稱、檔名與狀態，不含檔案內容。

網頁回應永遠優先

轉檔行程降優先權並限制可用核心數（預設保留一顆給網頁），轉大檔時介面不會卡住 —— 轉檔本身只會慢一點。派送前先估算記憶體，不夠就留在佇列排隊，不會硬開下去把機器打爆；作業狀態存在資料庫，服務重啟後不會憑空消失。

優先派送（插隊）

管理員可指定少數幾位使用者 —— 高階主管、或有時效性的重要工作 —— 他們送出的作業直接排到佇列最前面，下一個被派送的就是他們的。不會中斷正在執行的作業（轉檔跑到一半殺掉只會留下半成品），效果是「下一個換你」而不是「現在就換你」；名單內的人彼此仍照先來後到，記憶體不足時一樣要排隊。

管理員看得到全部

全站作業一覽：誰送的、哪個工具、哪個檔、排第幾位、跑多久，可只看進行中，每一筆都能直接取消。維護前可暫停派送，讓手上的跑完但不再開新的（已在執行的轉檔是獨立子行程，凍結不了 —— 介面照實說明，不會讓人以為按了就停）。

效能看得見、上限調得動

執行中 / 排隊中數量、Office 轉檔佔用、CPU 與記憶體用量都在同一頁，點一下看歷史趨勢圖；記憶體是實測子行程的數字（真正吃記憶體的是 soffice）。五個併行上限全部可調，而且填再大也會被實際可用記憶體夾住。

v1.14 新功能

AD / LDAP 目錄整合：網域控制站容錯與帳號集中管理

目錄服務整合之後，實務上常見的問題包括：主要網域控制站重新啟動、權限設定在主要群組上卻未生效、離職人員的帳號仍可使用、帳號遭他人冒用。以下機制分別處理這些情況。

多台網域控制站容錯

伺服器位址可以填多台（逗號或換行分隔），依序嘗試 —— 主要 DC 維護或重啟時，登入自動換下一台，不會變成全公司登不進來。連線與查詢都有逾時，DC 不通時幾秒內就回明確訊息，不會讓使用者枯等到以為系統掛了。掛掉的 DC 修好之後會自動回到輪替。

AD 主要群組也算數

AD 的主要群組（primaryGroupID）不會出現在 memberOf —— 這是 AD 整合最容易踩到的坑：企業把某個部門設成主要群組，權限掛上去之後成員一個都拿不到，而且在 AD 使用者的「成員隸屬」分頁也完全看不出原因。現在會自動把主要群組一併納入權限解析。OpenLDAP 沒有這個概念，行為完全不受影響。

離職 / 停用的帳號看得見

目錄同步原本只增不減：AD 那邊把人停用或刪掉之後，本站的帳號、角色指派、群組成員關係全部還在，「這個系統裡還有誰」答不出來。現在使用者清單多了「目錄已無」與「AD 已停用」兩個檢視與徽章。判定只認完整掃描 —— 帶名稱過濾的同步只看得到一部分目錄，拿它當基準會把整個組織誤標成離職。

批次停用，而且有安全閥

「目錄已無」可能好幾百人、橫跨十幾頁 —— 一鍵全部停用，按下去之前會先試算並告訴你實際會動到幾個人。也可以設成同步後自動停用（預設關閉）。關鍵是安全閥：一次要動的人數超過目錄帳號總數的 20% 就整批中止、一個都不動 —— 服務帳號密碼過期、搜尋範圍被改都會讓「全公司都不見了」，那時候什麼都不做才是對的。而且只停用不刪除，帳號與權限指派都保留，人回來時按一下就恢復。

現在有誰登入著

使用者清單直接顯示線上人數（同一個人開三個瀏覽器算一位），每個帳號可以看目前的登入裝置 —— 瀏覽器與作業系統、來源位址、最後活動時間 —— 並個別或全部強制登出，動作留在稽核記錄裡。帳號可能外洩時，不必改密碼就能先把所有裝置踢掉。

權限指派不必等對方先登入

目錄瀏覽裡點任何一位使用者就能直接指派角色，不必等他先登入過一次 —— 新人報到當天就能用。「所屬群組」每一列也能當場設群組權限。原本只能指派給整個 OU，但「這個 OU 裡只有這兩個人是財務」才是實務上最常見的需求。

「他到底能用什麼」一眼看完

權限來源散在四個地方（直接指派的角色、群組含巢狀上層群組、OU、直接工具授權），出事時很難說明。編輯使用者時可以展開有效權限面板：這個人最終能用哪些工具、每一項是哪一條規則給的。稽核回應與交接說明直接照著念。

密碼快到期，先看到

密碼到期對使用者的症狀是「突然登不進來」，然後才來問管理員。現在清單會標出幾天後到期（已過期另外標示），可以事先提醒。日期是讀 AD 自己算好的值，所以套了細緻密碼原則（PSO）或設了「密碼永久有效」的人都正確 —— 用網域的全域設定自己推算會算錯。

為什麼分兩個

合規規範要求「管系統的人」與「看記錄的人」職責分離 — admin 不該偷看 user 真實上傳的檔案內容、稽核員不該動系統設定。任一方都不擁有完整存取權，這就是 separation of duties。

強制 TOTP 2FA

稽核員角色第一次登入會被導向 /2fa-verify 自動 setup（顯示 QR code）→ 用 Google Authenticator / Microsoft Authenticator / Authy / 1Password 任一掃描 → 輸入 6 碼完成。稽核員自己不能停用 2FA，admin 也無法替稽核員角色用戶取消強制。

多稽核員支援

除了內建 jtdt-auditor，admin 可用 sudo jtdt audit-user create <name> 加任意數量的稽核員（適合大公司 IT / 法務 / 內稽分權審視）。每個稽核員獨立 2FA。

稽核員自身行為留痕

稽核員每次 view 寫一筆 auditor_view audit event（path / method / IP），admin 看得到稽核員看了什麼，但稽核員自己刪不掉（UI 無刪除端點，本身就唯讀）。

所有 user 都能用 2FA

不只稽核員 — 任何 user（包含 LDAP / AD 帳號）可在「我的帳號」modal 自助啟用 TOTP 2FA。已啟用後可隨時停用（auditor 角色除外）。

緊急復原 CLI

admin 可離線復原：jtdt auth show / disable / set-local、jtdt reset-password <user>、jtdt audit-user create。即使忘密碼 / LDAP 設錯不需重灌、不會掉資料。

資料保護與合規

文件留在哪裡、哪些情況會連到外部、工具本身做到的控制與你的組織要做的事，並對照個資法、GDPR、ISO/IEC 27001:2022 與 ISO/IEC 42001:2023 的條文與控制項。

看資料保護與合規

不上雲，資料留在自己手中

所有檔案處理只發生在你的伺服器上。
可在 Linux 架站給內網多人使用，或單機本地用，不上傳任何雲端服務。

依資安指引實作

部署前請注意
  • 只在內網或 VPN 使用。同仁會拿它處理合約、報價、個資等機密文件。放在公開網路上，任何人都能試著登入、上傳特製的檔案；放在內網，連得到的只有同仁，而且都要先登入。
  • 不是本機一個人用，就放在反向代理後面。應用程式預設只聽 127.0.0.1:8765（純 HTTP）；多人或從其他電腦使用時，請由 nginx、Caddy 等反向代理提供 HTTPS，不要把 :8765 直接開放到網路上。
  • 一定要對外開放時，風險自負。至少加上認證與強制雙因素驗證、WAF 或速率限制，並持續更新相依套件。各種反向代理的設定範例見 OPS.md 反向代理章節。

部署到 Linux server，到「認證設定」啟用本機帳號 / LDAP / AD，搭配角色與權限矩陣 + 稽核 + 記錄轉送。內網多人共用，可控管。

⚠ 對外存取一律走 nginx 反向代理 + HTTPS：建議 :8765 維持只聽 127.0.0.1，由 nginx / Caddy 反向代理對外提供 HTTPS（TLS 終結 + HSTS + 憑證）。不要直接 bind 0.0.0.0 把純 HTTP 對網路開放（明文傳帳密）。反向代理設定見 OPS.md。

（若內網受信任、暫時要直接對內網開放，jtdt bind 0.0.0.0 會改 systemd / launchd / Windows Service 設定並重啟；要綁特定 port 例 jtdt bind 0.0.0.0:9999。Linux / macOS 前面加 sudo，Windows 以系統管理員身分執行 PowerShell。）

curl -fsSL https://raw.githubusercontent.com/jasoncheng7115/jt-doc-tools/main/install.sh | sudo bash
Windows 10 / 11（x64・ARM64）
下載安裝程式 到 GitHub Releases 下載 jt-doc-tools-x.y.z-setup.exe，按兩下安裝， 不必開 PowerShell 貼指令。安裝精靈為繁體中文，含解除安裝功能。
檔名上的版本比較舊沒有關係 —— 這支安裝程式只是個引導程式， 實際的程式碼是安裝當下才從 GitHub 下載的，所以裝起來一定是最新版。

或用 PowerShell 一行指令安裝（以系統管理員身分執行）：

$f="$env:TEMP\jtdt-install.ps1"; try { Invoke-WebRequest 'https://cdn.jsdelivr.net/gh/jasoncheng7115/jt-doc-tools@main/install.ps1' -OutFile $f -UseBasicParsing -TimeoutSec 15 -ErrorAction Stop; powershell -NoProfile -ExecutionPolicy Bypass -File $f } catch { Write-Host "[X] 下載安裝腳本失敗：$($_.Exception.Message)" -ForegroundColor Red; Write-Host "請檢查網路（VPN？防火牆？DNS？）後重試。" -ForegroundColor Yellow }; Read-Host '按 Enter 關閉'

安裝完成後，瀏覽器開 http://127.0.0.1:8765/ 即可使用。

公司網路連不到 GitHub / PyPI？ 兩條路都可以：①在有網路的機器建 Docker 映像檔， docker save 成單一檔案（約 940 MB）帶進內網 docker load 就能跑；②有公司 PyPI 代理時直接照常安裝， 指向代理即可（之後也能照常 jtdt update）。 步驟見 OFFLINE.md。
系統需求 Ubuntu 20.04+ / Debian 11+ / macOS 12+ / Windows 10 1809+ / 磁碟 12 GB 整機/VM/LXC 容量(最低,建議 20 GB+；OS 基底 ~2 GB + 安裝峰值 ~8 GB + 緩衝；完成後常駐 ~3 GB)/ RAM 2 GB（建議 4 GB+）/ x86_64 或 arm64（Apple Silicon、Win11 ARM 都支援）。 不需預裝 Python（uv 自動下載獨立 3.12）。 安裝時長 5-15 分鐘（PyTorch 700 MB 是大頭，依網速）。
升級 / 移除

⚠ 2026-09-13 之前用 git 安裝的，這一版升級前要先跑一行。 專案改寫過 git 歷史（移除一筆誤入版控的資料），舊版的 jtdt update 會在 git fetch --tags 失敗（would clobber existing tag）， 訊息只說 git fetch failed。先跑 git -C <安裝目錄> fetch --tags --force origin 一次即可永久解決 （是大寫的 -C；小寫的 -c 是設定參數， git 不會切到那個目錄，會回「not a git repository」， 看起來像安裝壞掉其實只是打錯一個字母）。 tarball 安裝與 Windows 安裝程式不受影響；v1.15.41 起已修正。

Linux / macOS
sudo jtdt update
sudo jtdt uninstall
Windows（以系統管理員身分執行 PowerShell）
jtdt update
jtdt uninstall
加 --purge 連同資料一起刪。
