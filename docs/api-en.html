API manual

Jason Tools Document Toolbox exposes a RESTful API. Every tool has an endpoint, ready to plug into automation, your own systems or scheduled jobs.

Basic principle: the API is open by default (matching the web UI); to lock it, an administrator turns on enforce mode on the admin “API Token” page and issues bearer tokens.

1. Authentication

Authentication disabled (default)

A new installation has authentication off, so every /api/* endpoint works straight away without a token.

1. Authentication

Enabling API tokens

An administrator goes to admin → API Token:

  1. Press "issue a new token" → give it a purpose (for example gitlab-ci) → receive a 64-character hex token (shown once only; keep it safe)
  2. Tick “Enforce; refuse anything without a token” and save

From then on every /api/* call must carry one of these:

Authorization: Bearer 64char-hex-token-here

or as a query string:

GET /api/jobs/abc123?token=64char-hex-token-here

Missing or invalid token → 401 Unauthorized JSON:

{"ok": false, "detail": "需要有效的 API token（Authorization: Bearer ...）"}

Tokens are managed from admin / jtdt Managed from the CLI, entirely separate from web authentication (jtdt-admin / LDAP / AD).

3. Document conversion API

Office format conversion

Converts between formats of the same kind: word processing ↔ word processing, spreadsheet ↔ spreadsheet, presentation ↔ presentation. Job mode; returns job_id.

Ask which target formats are available before submitting a conversion. The values of target differ from one installation to another (without the Impress module there is no presentation group), so do not hard-code the ids in your own program:

GET /tools/office-convert/formats
curl -s http://localhost:8765/tools/office-convert/formats \
  -H "Authorization: Bearer YOUR_TOKEN" | jq
# → {"families": [{"id": "text", "name": "文書檔",
#                  "sources": ["odt", "docx", ...],
#                  "targets": [{"id": "docx-2007", "ext": "docx",
#                               "label": "Word 2007", "note": "...",
#                               "common": true}, ...]}, ...]}
POST /tools/office-convert/convert
ParameterTypeRequiredDescription
filefile✓Office document; may be repeated (several files come back as a ZIP)
targetstr✓The target format id, taken from formats above

Files in one request must all be of the same kind (a spreadsheet and a word-processing file cannot be mixed) and must match the kind that target belongs to, otherwise the call returns 400.

# 文書檔：.odt 轉成 Word 97–2003
curl -X POST http://localhost:8765/tools/office-convert/convert \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@報告.odt" -F "target=doc" | jq
# → {"job_id": "...", "download_url": "/api/jobs/.../download"}

# 簡報：.pptx 轉成 ODF 簡報
curl -X POST http://localhost:8765/tools/office-convert/convert \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@簡報.pptx" -F "target=odp" | jq

.docx / .xlsx / .pptx each offer two targets; the difference is the Compatibility mode is more than just a name:

Target idProducesCompatibility mode

docx-365Word 2010; 365 format15
xlsx-2007 / xlsx-ooxmlExcel 2007–365 / Office Open XML—
pptx-2007 / pptx-ooxmlPowerPoint 2007–365 / Office Open XML—

Response: {"job_id": "...", "download_url": "..."}. One file comes back in the target format, several come back as a ZIP. On failure, 4xx plus JSON {"detail": "..."}.

3. Document conversion API

PDF to images

Converts each page of a PDF or office document to PNG / WebP / JPEG (multiple pages are bundled into a ZIP). The size can be set by DPI or by a fixed width (every page is scaled to the same width; the height follows the page's proportions).

POST /tools/pdf-to-image/convert
GET  /tools/pdf-to-image/download/{upload_id}
ParameterTypeRequiredDescription
filefile✓PDF or office document (anything that is not a PDF is converted to PDF first)
formatstringOutput format: png (default) / webp / jpeg (jpg is accepted too); any other value returns 400
widthintWidth of every page in pixels (16 to 10000); when given, dpi is ignored. Out of range returns 400 rather than quietly using a different width
dpiintResolution used when width is not given; default 200, range 72 to 600
qualityintWebP / JPEG quality, 1 to 100, default 80; PNG is lossless and ignores it

A page over 40 million pixels (or, in WebP, over 16383 px on either side, a limit of the format itself) is output smaller; that page has reduced set to true, and the top-level reduced_pages lists which pages.

# 1. 上傳並轉換（網頁用：WebP、寬 1920）
curl -X POST http://localhost:8765/tools/pdf-to-image/convert \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@slides.pdf" -F "format=webp" -F "width=1920" | jq
# → {"upload_id": "...", "page_count": 3, "format": "webp", "size_mode": "width",
#    "width": 1920, "dpi": null, "reduced_pages": [], "pages": [{"width_px": 1920, ...}]}

# 依 DPI 轉 PNG
curl -X POST http://localhost:8765/tools/pdf-to-image/convert \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@document.pdf" -F "dpi=200" | jq

# 2. 下載
curl -s http://localhost:8765/tools/pdf-to-image/download/abc123 \
  -H "Authorization: Bearer YOUR_TOKEN" --output pages.zip

Response: step 1 returns each page's details (width_px / height_px / dpi / size_bytes / reduced) and the upload_id; step 2 returns the images: a single image in the chosen format for one page, or a ZIP for several (each page named like slides_p1.webp).

PDF bookmarks and contents

Adds bookmarks to a PDF (the navigation panel on the left of the reader) and a clickable table of contents page. Several files are joined automatically, with each file name becoming a first-level bookmark; bookmarks inside each document move one level down and are kept. Accepts PDFs and office documents (office documents are converted to PDF first).

POST /tools/pdf-bookmark/api/pdf-bookmark
ParameterTypeRequiredDescription
filesfile[]✓One or more PDF / office files; several are joined in order
bookmarksstrSupply the bookmarks yourself (a JSON array of {"title","page","level"}). If given, this replaces the automatically generated ones
autoboolDetect headings automatically from the font size, default false (only applies with no bookmarks and a single file)
toc_pageboolInsert a table of contents page, default false. The web interface has this ticked by default, while the API keeps false so that existing automated calls do not suddenly gain a page

Scan cleanup

Straightens documents that were photographed or scanned at an angle, trims dark borders and evens out uneven background. For phone photos it finds the four corners of the sheet and corrects the perspective. No AI and no GPU involved (classical image processing; about 0.8 s per page on CPU at 200 dpi).

ParameterTypeRequiredDescription

Known misheard spellings (since v1.16.49): if you already know how a word gets misheard, write one line "misheard spelling → correct spelling" (the arrow can also be -> or =>; separate several misheard spellings with enumeration commas or commas), for example Proksmox、Proxmux → Proxmox. The speech service replaces them as listed before correction: no language model is involved, it happens at every correction level, and the raw recognition layer is unchanged; misheard words spelled very differently, which correction cannot recognise, can only be fixed this way. English must match as a whole word and ignores case; Chinese matches literally, so a very short Chinese misheard spelling may be replaced inside other words; make it specific. The correct spelling is also sent as a term. The rules follow the speech service: at most 20 misheard spellings per term, each 2–200 characters; only one term to the right of the arrow (enumeration commas, commas, semicolons, |, ／ or a / with a space on either side separate terms; TCP/IP is one term); a misheard spelling must not be another term on the list (replacing it would change correctly written text; a list line written as Proxmox VE / PVE counts as the two terms Proxmox VE and PVE); the same misheard spelling must not point to two terms. A line that breaks these returns 400 naming the line and is not sent. Lines with two or more arrows, lines starting with # and sentences are still meeting background. Only speech service interface version 2.9 and later accept them; with an older version (or when the version cannot be read) they are not sent and variants_sent in the response is false.

Lines written as sentences are not sent as terms (since v1.16.44): a line with a full stop, exclamation or question mark, or with a piece longer than 40 characters / 10 Han characters, is treated as meeting background. A whole sentence as a term is pointless: correction would keep it as written and match spellings against it. For a line like "Attendees: Wang Xiaoming, Bianca" the label before the colon is not sent and the rest is sent as a list; a line that is only a label ("Attendees are:") is not sent; heading lines starting with # and pieces with no letters at all (dates, times, plain numbers) are not sent either (v1.16.48). The full text is in the response's context and goes into the meeting background when the transcript is sent to Meeting summary.

Which speaker-separation method is used depends on the speech service version (from v1.16.31): when the speech service is on interface version 2.5 or later, this system asks for NVIDIA Nemotron; on 2.4 or earlier (or when the version can't be read) the original method is used. The response field speaker_engine shows which one this job requested. The speech service measured both on the same real recognition output with no speaker count given: speaker errors fell from 18.52% to 2.92% on 20 Chinese meetings and from 12.31% to 4.65% on 16 English meetings.

The same num_speakers means opposite things under the two methods:

Nemotron (speaker_engine = auto)Original method (legacy)
The number you giveOnly an upper limit: speakers are merged only if more are found; fewer are left as they areForces exactly that many groups
Higher than the real countNo effectSplits the main speakers apart
Lower than the real countMerges different people into one speakerMerges different people into one speaker
AdviceLeave 0 if unsure; err on the high sideLeave 0 if unsure; don't count people who say only a sentence or two

Under Nemotron, giving the correct count instead of none differs by only 0.01 percentage points (20 meetings, 95% confidence interval [−0.03, 0.00]). That only shows it is no worse; don't fill it in expecting better accuracy.

The new method separates at most 8 speakers. If you specify more than 8, the speech service always falls back to the original method; if you don't, it falls back only when the new method fills all 8 slots and the original method finds more than 8 speakers, otherwise it keeps the new method with at most 8 speakers. When it falls back, the reason is in the response fields diarization.reason (code) and diarization.note (explanation). For meetings you know have more than 8 speakers, specify the number.

auto only listens to about the first 30 seconds of speech and uses that language for the whole meeting; it does not decide per segment. If someone speaks another language at the start (20 seconds is enough), the whole meeting may be recognised wrongly; silence or background noise at the start does not matter. When you know the language of the whole meeting, set it. For meetings where whole sentences alternate between Chinese and English, set the language used most: whole sentences in the other language are mostly not recognised correctly (English terms inside Chinese sentences are fine).

This endpoint is synchronous: a 37-minute meeting measured 7 to 8 minutes (recognition plus speaker separation plus correction), so give the caller a generous timeout. For background processing use the web path instead (POST /upload → POST /start → poll /api/jobs/{id} with the job id).

The matching rules are fixed and err on the side of suggesting less: in English, one or two letters off, or an extra space or hyphen in the middle; in Chinese, three to eight characters where every character has a matching pronunciation (same sound, different character). Put the ones you pick into replacements of /api/meeting-summary and they are applied before the analysis: English is replaced as whole words (Biankas is not cut into), and the response gains replacements (what was actually replaced and how many times; pairs that matched nothing are left out). The .json exported from the web page carries the transcript, where each changed segment keeps its original text in orig_text.

Spellings the suggestions do not catch (when recognition misheard too much, e.g. Groxmoxity for Proxmox) can go into replacements yourself; the same rules apply. English replacement is case-sensitive, so add a separate pair to also replace the lowercase groxmoxity.

Replacement mode (mode=replace)

Export details:

  • ODT is built by the program itself and needs no Office engine; Word and PDF (docx / pdf) go through the Office engine and return 503 when there is none.
  • The page header says "draft" by default; set draft_mark to false to leave it off. The file name comes from title (up to 40 characters, with characters not allowed in file names removed), so the download is named <title>-草稿.<fmt>.
  • The font is DFKai-SB. When the server does not have it, the PDF uses another regular-script font, and failing that a Ming (serif) font.
  • JSON carries "format": "jtdt-official-doc" and "format_version": 1 and holds the whole case; draft.text is replaced by the text you send and draft.issues is re-checked against it.
  • The electronic document DI file (di) is the body file (XML) of a Taiwan government electronic document, following the version 104 DTD of the National Archives Administration's computerised records management rules (letter 104_2_utf8.dtd, memo 104_5_utf8.dtd). Officers import it into their agency's own document system and then number, approve and send it as usual. Date of issue, document number and reference number stay empty when empty and are kept whole when given; agency codes come from org_codes first, otherwise from the address book by name (filled only when exactly one agency has that full name). Handling notes have no DI file, and a draft without a subject line cannot produce one; both return 400. Response header X-Jtdt-Di-Valid says whether it passed the DTD check (1 or 0), and X-Jtdt-Di-Notes how many remarks there are.
  • Images (png / svg) use the same layout as the PDF: one page returns that image (PNG at 200 dpi; SVG text is converted to outlines so it looks the same without the font), several pages come as one image per page in a zip (<title>-草稿-png.zip), up to 30 pages.

11. Administration API

Signed-URL file fetch (not meant to be called by hand)

Some external services only accept a URL — the file is not uploaded to them, they fetch it themselves from an address we provide. In that case we hand over a short-lived signed URL rather than an API token:

GET /api/speech/audio/{file_id}?exp=<到期的 unix 秒數>&sig=<簽章>
  • The URL itself is the authentication, with no Authorization header. The signature binds the file id together with the expiry,

so extending exp invalidates the signature.

  • Anything that fails to verify returns 404 — a malformed id, a wrong signature, an expired URL and a missing file all

look identical from outside (a 403 would tell the caller “that id exists”).

  • The URL is produced server-side, and there is no public endpoint that hands out a signature —

it is listed here so that this document misses no endpoint, not for you to call.

If a fetch returns 404, the usual cause is an expired URL, not a missing file.

#!/bin/bash

  -H "Authorization: Bearer $TOKEN" \
  --output reviewed.pdf

14. Rate limits and upload size

There is no built-in rate limit at present. Add one at the reverse proxy (nginx / Caddy) when you deploy:

  • client_max_body_size 100M (required, otherwise large PDFs are rejected)
  • proxy_read_timeout 900s + proxy_send_timeout 900s (required; a single LLM inference often takes 5-15 minutes, and the 60s default is guaranteed to give a 504)
  • proxy_buffering off (friendly to LLM streaming)
  • With several layers of nginx (a self-hosted LLM proxy plus jt-doc-tools) every layer needs it; one layer left at the default breaks the whole chain
  • If it needs to be exposed publicly, add limit_req_zone against abuse

See the "reverse proxy" section and the "504 Gateway Timeout troubleshooting" section of OPS.md.
