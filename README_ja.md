> 今いる場所で `.git` を探します。このメッセージは**「インストール先が git 管理ではない」ように読めますが、
> 実際には 1 文字打ち間違えただけです**（2026-09-14 お客様からの報告）。
>
> 以降 `jtdt update` は通常どおり動作します。**影響を受けないもの**：tarball でのインストール、Windows インストーラー、

## ワンライナーでインストール

### システム要件

| 項目 | 最低 | 推奨 |
|---|---|---|
| OS | Ubuntu 20.04+ / Debian 11+ / macOS 12+ / Windows 10 1809+ | いずれも最新版 |
| ディスク容量 | **12 GB** の実機 / VM / LXC 容量（最低）| **20 GB+**（データディレクトリの増加分を含む） |
| メモリ RAM | 2 GB の空き | 4 GB+ |
| CPU | x86_64 / arm64（Apple Silicon、Win11 ARM のどちらも可）| 4 コア+ |
| ネットワーク | インストール時に GitHub / PyPI へ接続できること（以降は社内ネットワークのみで動作）| — |
| Python | 3.10+（インストールスクリプトが uv-managed Python を自動で用意します） | — |

> **ディスク使用量の内訳**（5-8 GB で足りそうに見えても下限を 12 GB にしている理由）：
> - **OS のベース**：Debian / Ubuntu の最小構成で約 1.5-2 GB。他のディストリビューションやデスクトップ入りではさらに増えます。
> - **インストール中のピーク 約 6-8 GB**：apt が一時的に保持する .deb パッケージ 約 1 GB（OxOffice / LibreOffice の依存）+ uv の wheel cache 約 1-2 GB（PyTorch 700 MB とその他）+ 展開時の中間ファイル。インストールスクリプトが自動で `apt-get clean` + `uv cache clean` を実行して解放しますが、**ピークの間**はこれだけ必要です。
> - **インストール完了後の常駐 約 3 GB**：Python 環境 約 1.5 GB（PyTorch / EasyOCR の主 OCR エンジンを含む）+ tesseract の学習データ 約 80 MB（chi_tra の fast+best 両変体 + eng）+ OxOffice/LibreOffice 約 1 GB。EasyOCR のモデルは初回の OCR 時にさらに約 150 MB をダウンロードします。
> - **データディレクトリの増加**：ユーザーがアップロードしたファイル + 監査記録 + 履歴が蓄積し続けます。データ用ディスクが厳しい場合は `JTDT_DATA_DIR=/mnt/big-disk/jtdt curl ... | sudo -E bash` で別の場所にインストールできます。
>
> **LXC / VM の構成の目安**：12 GB は通る下限です（OS 2 GB + ピーク 8 GB + 余裕 2 GB）。本番運用では 3 か月後に再び逼迫しないよう、最低 20 GB を割り当ててください。**8 GB の LXC では確実に入りません**（すでに顧客が踏んでいます）。

**Windows 10 / 11 —— ダブルクリックでインストール（推奨。PowerShell を開く必要はありません）**：

[GitHub Releases](https://github.com/jasoncheng7115/jt-doc-tools/releases/latest) から次をダウンロードし
`jt-doc-tools-x.y.z-setup.exe` をダブルクリックして実行するだけです。インストールウィザードは繁体字中国語で、アンインストール機能も含みます。

> **ファイル名のバージョンが古くても問題ありません。** このインストーラーはブートストラップにすぎず（約 6 MB）、
> 実際のプログラムは**インストール時に GitHub からダウンロードされます**。そのため、手元の .exe がどのバージョンでも
> インストールされるのは最新版です。インストーラー自体は、インストールの流れを変える必要があるときにだけ再配布します。

**Windows 10 / 11 —— PowerShell のワンライナー**（管理者として実行してください）:
```powershell
$f="$env:TEMP\jtdt-install.ps1"; try { Invoke-WebRequest 'https://cdn.jsdelivr.net/gh/jasoncheng7115/jt-doc-tools@main/install.ps1' -OutFile $f -UseBasicParsing -TimeoutSec 15 -ErrorAction Stop; powershell -NoProfile -ExecutionPolicy Bypass -File $f } catch { Write-Host "[X] 下載安裝腳本失敗：$($_.Exception.Message)" -ForegroundColor Red }; Read-Host '按 Enter 關閉'
```

インストール後はブラウザーで **<http://127.0.0.1:8765/>** を開けば使えます。

> インストール時間は約 5-15 分です（回線速度によります —— PyTorch の 700MB が大半です）。回線が遅い環境では、切断に備えて先に `screen` / `tmux` でバックグラウンドにしてから実行することをおすすめします。

詳しいインストール手順は **[INSTALL.md](INSTALL.md)** をご覧ください（必要なツール、プラットフォームごとの違い、アンインストールを含みます）。

## 51 のツール一覧

### フォーム入力と押印
- **フォームの自動入力** —— 項目の自動検出 + テンプレートによる入力
- **押印と署名** —— ドラッグ＆ドロップで印章 / 署名を適用
- **透かし** —— テキスト / 画像の透かし。複数ファイルの一括処理に対応

### ファイル編集
- **ページエディタ** —— テキストボックス / 図形 / 白地 / 蛍光ペン / 署名 / 注釈 / オブジェクトの実削除
- **ページの整理 / 回転 / ページ番号 / 複数ページの結合 (N-up)**
- **ページへの枠線追加** [OxOffice/LibreOffice が必要] —— 各ページに枠線を追加します。太さ / 色 / 線種 / 角丸 / 内外の二重枠 / 影を設定でき、ページの端から内側へ、または内容に合わせて配置し、対象ページの指定と最初のページの除外もできます。スライドへの枠線追加が主な用途で、PDF と文書ファイルを受け付けます（文書ファイルの入力にはエンジンが必要です）
- **スキャン補正** [OxOffice/LibreOffice が必要] —— 傾いて撮影・傾いてスキャンされた文書の黒い縁を切り落とし、傾きを直し、むらのある下地をならします。スマートフォンでの撮影では紙の四隅を検出して透視補正し、ページごとに補正角度と残りの傾きを報告します。PDF、画像、文書ファイルを受け付けます（文書ファイルの入力にはエンジンが必要です）
- **割印** [OxOffice/LibreOffice が必要] —— 1 つの印章を数片に切って連続したページにまたがって押すため、**差し替えやページ抜けが一目でわかります**（その一片が合わなくなります）。側辺の割印と見開きに対応し、1 つの印が何ページにまたがるか、位置と角度を固定するかランダムにするかを設定できます。印章はアセットライブラリから選ぶ、自分でアップロードする、文字からシステムに生成させる、のいずれも可能です（文書ファイルの入力にはエンジンが必要です）
- **ページサイズの統一** [OxOffice/LibreOffice が必要] —— サイズが混在したページを 1 種類の用紙（A4 / A3 / 任意）にそろえます。縮小して余白、縮小せず中央、切り取って埋める から選べ、縦横の混在は自動で向きを合わせます。**内容はベクターのまま保たれ、テキストも選択できます**（画像には変換しません）。入札案件では A3 の図面と A4 の本文が混在しがちなので、印刷・製本の前に統一します（文書ファイルの入力にはエンジンが必要です）
- **ファイルの結合 / ページの分割**
- **しおりと目次** [OxOffice/LibreOffice が必要] —— PDF にしおり（ビューアの左側のナビゲーション）とクリックできる目次ページを追加します。**複数のファイルを選ぶと自動で連結し、ファイル名で第 1 階層のしおりを作成します**。子文書の元のしおりは 1 階層下げて保持するため、入札案件 / 年次報告書のように十数個のファイルから数百ページになる文書で特に効果があります。見出しの自動検出や、既存の目次リストの貼り付けもできます（文書ファイルの入力にはエンジンが必要です）
- **スキャンの合成** —— 複数のスキャンを読み込ませると、内容のあるブロックを自動で切り出し、元の色を保ったまま元の位置どおりに 1 枚の A4 白地へ合成します。証明書類の表裏が主な用途で、ドラッグで微調整でき、薄い灰色の下地は自動で白くします

### 内容の処理
- **テキスト / 画像 / 添付ファイルの抽出** —— LLM による段落の再構成オプション付き
- **文字数の集計** [OxOffice/LibreOffice が必要] —— 表 + グラフ + LLM の要約。PDF / オフィス文書 / プレーンテキストを受け付けます
- **会議要約** [OxOffice/LibreOffice が必要] — 文字起こし（.vtt / .srt / .json / .txt / .docx / .odt）を要約・決定事項・タスク・リスク・章立てに整理します。**各項目は元の発言箇所と話し手まで遡れ**、クリックするとその箇所へ移動します。タイムスタンプがある場合は発言割合も算出します。PDF / Word / ODF / Markdown / グラフ PNG / JSON に書き出せます
- **会議録音の文字起こし** — 録音・録画を**タイムスタンプと発言者付き**の文字起こしに変換し、ワンクリックで「会議要約」へ渡せます。認識は音声サービス（JTLW）側で実行するため、**管理画面で設定するまで表示されません**
- **公文書の起案** [OxOffice/LibreOffice が必要] — 平易な言葉で書いた用件から台湾の行政機関の「簽」（主旨・說明・擬辦）や「函」（呼称と結びの言葉は行文関係で決まります）を作るか、来文と処理方針から「簽辦意見」を作ります。**書式はプログラムが組み立て、中身は LLM が書きます**。金額・日付・法令・条番号・文書番号や「業經核准」のような表現は入力内容と突き合わせ、根拠のないものを指摘し、入力にない情報は〔待補〕と記します。段落ごとの書き直し、版の保存、**案件履歴**からの再開、管理者が用意した**公文ナレッジベース**の参照（「業務上の根拠」だけを根拠として扱います）ができ、書き出しでは政府オープンデータの公文テンプレートを使えます（管理者がダウンロードした後）。**照合で意味までは確かめられません**（因果や結論）。下書きは送る前に必ず人が確認してください。出力は常に繁体字中国語の台湾の公文書式で、英語 / 日本語の画面でも使えます。プレーンテキスト / ODT（エンジン不要）/ Word / PDF（Word と PDF はエンジンが必要）に書き出せます。電子公文書の DI ファイル（XML。機関の公文書システムへの取り込み用。受信者などの機関コードはアドレス帳から入ります）もエクスポートできます。
- **注釈の整理 / 消去 / フラット化**
- **OCR 文字認識** —— スキャンした PDF / 画像を OCR にかけて、検索でき、マウスで選択してコピーできるようにします（macOS プレビューの Live Text と同じ考え方です）。2 つのエンジン（**EasyOCR** が既定で、日中韓の認識精度が高く、**Tesseract** が予備）を備え、LLM による typo の補正も選べます。**外部 GPU 認識サーバーに対応**（DGX Spark / H100 / 4090 など）。管理画面から `install.sh` をダウンロードすればワンクリックで配置でき、1 ページあたりの認識時間が CPU の 8-15 秒から GPU の 0.3-0.8 秒になります（**10 倍以上**）。
- **送付前チェック** —— 一括での検収：ページサイズ、フォントの埋め込み、項目の欠落、機微情報の残留、隠れた内容
- **リスト処理** —— テキストを貼り付ける / .txt / .csv / .xlsx / .docx / .pdf などのファイルをアップロードし、1 行 1 件として並べ替え / 重複除去 / 絞り込み / 先頭末尾の抽出 / 大文字小文字の変換などを行います。複数の操作を組み合わせられ、結果はワンクリックでコピーするか .txt / .csv / .xlsx でダウンロードできます
- **電子請求書の処理** —— 台湾の電子請求書の QR コードを読み取って請求書番号 / 日付 / 金額 / 統一番号を取り出し、売り手の会社名、業種、勘定科目を自動で入力します（ルール + 任意で LLM 判定）。経費精算チェックと当期の請求書チェックに対応し、.xlsx / .ods / .csv / .json / .xml / .txt / .md でエクスポートできます（見出しはカスタマイズ可能）
- **乗車証明の整理** —— 台鉄の購入証明 / 台湾高鉄の電子チケット証明 / Uber の乗車レシートの PDF をまとめて読み込ませると、日付 / 交通手段 / 出発-到着 / 費用を自動で表に整理します。項目はカスタマイズでき、.xlsx / .ods / .csv / .json / .xml / .txt / .md で経費精算用にエクスポートできます
- **統一番号の照会** —— 8 桁の統一番号を入力して逆引きするか、会社 / 機関 / 学校の名称、住所、業種のキーワードであいまい検索します（一致した文字を強調表示します）。分類での絞り込み、一括照会、CSV エクスポート付き

### 形式変換 [OxOffice/LibreOffice が必要]
- **オフィス文書 → PDF** —— オフィス文書を一括で PDF に変換します
- **オフィス文書の形式変換** —— 同じ種類の文書どうしの相互変換：文書ファイル（.odt / .docx / .doc / .rtf / .txt）、表計算（.ods / .xlsx / .xls / .csv）、プレゼンテーション（.odp / .pptx / .ppt）がそれぞれ相互変換できます。`.docx` / `.xlsx` / `.pptx` ではバージョンも指定できます（Word 2007 または Word 2010–365 など）
- **文書を画像に変換**：PDF やオフィス文書の各ページを PNG / WebP / JPEG に変換。DPI か幅を直接指定できます。複数ページは自動で ZIP にまとめます
- **画像 → PDF**
- **PDF → Markdown** —— PDF を構造化された Markdown に変換し、見出し / 表 / 太字を保持します。LLM や RAG の前処理に向いています
- **Markdown → オフィス文書** [OxOffice/LibreOffice が必要] —— Markdown を貼り付けるかドラッグし、テーマを適用して PDF または文書ファイル（.docx / .odt）として出力します。全ページのプレビュー付きです
- **PDF → 文書ファイル** —— PDF を文書ファイル（.docx / .odt）に逆変換します。3 つのエンジンから選べます：pdf2docx（定番で安定）、自社の jtdt-reform（幾何的なルールで編集しやすい本文に再構成）、自社の jtdt-layout（レイアウトが原本に最も忠実：ページ固定のテキストボックスで、位置 / 画像 / 枠線をほぼ 1:1 で保持）
- **PDF → プレゼンテーション** —— PDF を PowerPoint (.pptx) / OpenDocument プレゼンテーション (.odp) に逆変換します。**1 ページが 1 枚のスライドに対応**し、スライドサイズは原本のままです（縦向きの PDF もそのまま再現します）。jtdt-layout のレイアウト再現エンジンを使います

### セキュリティ処理
- **文書の匿名化 / テキストの匿名化** —— マイナンバー / 電話番号 / 銀行口座 / 統一番号 / AD DN など 14 種類以上の機微情報に対応します。
  処理は 3 種類です：**墨消し**（黒く塗って本当に削除）、**マスキング**（`0912****678`）、**置き換え**（見た目は普通だが実際とは違う値にします。システムのテストや外部に見せるレポートに向いています）
- **PDF の暗号化 / 復号**
- **メタデータの消去**
- **隠れた内容のスキャン**
- **文書の差分比較 / テキストの差分比較**
- **一文ずつ翻訳**
- **文書の翻訳** [OxOffice/LibreOffice が必要] —— オフィス文書全体を別の言語に翻訳し、**同じ形式・同じレイアウト**のファイルを出力します（テキストだけを置き換え、レイアウトは組み直しません）。.doc / .docx / .odt、.xls / .xlsx / .ods、.ppt / .pptx / .odp に対応し、翻訳後は先頭 6 ページのプレビューが付きます
- **圧縮**

> [OxOffice/LibreOffice が必要] と記したツールは OxOffice / LibreOffice を使います（OxOffice を優先します。OSSII が維持する台湾ローカライズ版の fork で、CJK のサポートがより充実しています）。他の 28 個のツールは PDF / プレーンテキスト / 画像のみを扱うため、Office エンジンは不要です。インストールスクリプトが自動で対応します。

## ユーザーのワークスペース（任意。管理者がオン/オフできます）

各ツールが出力したファイル（PDF / PNG、Word / Excel / PowerPoint、OpenDocument、プレーンテキスト）をサーバー上に一時保存し、ツール間で受け渡せます。いちいちダウンロードして再アップロードする必要はありません。

- **ワークスペースに保存** —— 各ツールが出力した PDF / PNG / Word / ODT をワンクリックでサーバーに残します。アカウント単位で分離され、本人だけが見られます。
- **ワークスペースから読み込む** —— どのツールのアップロード欄からもワンクリックで取り出せます（OCR → 押印 → 匿名化 …）。ファイルを探し直す必要がありません。
- **マイワークスペースのページ** —— トップページでのサムネイルプレビュー（PDF は 1 ページ目をレンダリング）、容量バーと保持期限、ダウンロード / 名前の変更 / 削除、複数選択での一括削除、ドラッグでの直接アップロード。
- **管理者による制御** —— 機能全体の有効 / 無効（無効にすると完全に非表示）、1 人あたりの容量、1 ファイルの上限、保持時間の一元設定、ユーザーの使用分の消去。
- **分離と安全性** —— 各ユーザーのファイルは本人だけが閲覧できます。認証が無効のときはスタンドアロンの共用ワークスペースになります。保持時間を過ぎたものはスケジュールが自動で削除します。

既定で有効です。管理者は「設定 → ワークスペース設定」でいつでも無効にできます。

## バックグラウンドジョブと完了通知

時間のかかる作業（形式変換、OCR、一文ずつ翻訳、大きなファイルの圧縮…）は、送信したらサーバーに任せられます。**そのままタブを閉じてかまわず**、進捗バーを見張る必要はありません。

- **送信すればバックグラウンドで実行** — 31 のツールがジョブシステムを通ります。PDF から文書 / スライドへの変換、形式変換、OCR、文単位の翻訳、オフィス文書から PDF、圧縮、結合、分割、透かし、押印、契印、提出前チェックなどです。
- **マイジョブ** —— 進捗、キューの順番、経過時間、結果のダウンロードがすべて同じページにあります。途中でキャンセルもできます。一文ずつ翻訳のように「出力が単一ファイルでない」ツールでは、戻ると元のページに復帰して対照表の続きを確認できます。
- **再起動しても消えません** —— ジョブの状態はデータベースに保存されるため、サービスの再起動後、未完了のものは中断として表示されます。音もなく消えることはありません。
- **マシンを落としません** —— ディスパッチの前にそのジョブが必要とするメモリを見積もり、足りなければキューで順番待ちさせます。同時処理数と Office 変換の並列上限は管理エリアで変更できます。
- **web の応答を優先** —— 変換プロセスは優先度を下げ、使えるコア数も制限します（既定で web 用に 1 つ確保）。大きなファイルの変換中でも操作画面は固まりません。
- **完了後は自動でワークスペースへ保存** —— すでにページを離れているときにだけ保存するため、自分で押した「ワークスペースに保存」と重複しません。
- **優先的な処理（割り込み）** —— 管理者は少数のユーザーを指定できます（経営層や、期限のある重要な作業）。その人たちが送信したジョブはキューの先頭に入ります。**実行中のジョブは中断しません** —— 効果は「次はあなた」であって「今すぐ交代」ではありません。リストの中では互いに先着順のままで、メモリが足りないときは同じく順番待ちになります。
- **何を待っているのかが見えます** —— ジョブ一覧には、使う共有リソース（Office 変換 / OCR / 外部サービス）が表示されます。3 つはそれぞれ並列上限を持つため、「なぜこんなに待つのか」がどれで詰まっているか一目でわかります。

管理者は「設定 → バックグラウンドジョブと並列度」でさらに次のことができます：

- **サイト全体のジョブ一覧** —— 誰が送信したか、どのツールか、どのファイルか、何番目か、何分動いているか。進行中のみの表示もでき、1 件ずつキャンセルできます。
- **ディスパッチの一時停止** —— メンテナンス前に、実行中のものは終わらせつつ新しいものは開始しないようにします。（実行中の変換は独立した子プロセスのため凍結できず、そのジョブをキャンセルするしかありません —— 画面にはそのとおり説明しています。）
- **性能と履歴** —— 実行中 / 順番待ちの件数、Office 変換の占有、CPU とメモリの使用量。クリックすると履歴の推移グラフを表示します。メモリは**子プロセスを実測した**数字です（実際にメモリを使うのは soffice で、私たちのスレッドではありません）。測定できない場合は推定値を表示し、その旨を明示します。
- **並列上限はすべて変更できます** —— 同時処理数、Office 変換の同時実行数、外部サービスの同時呼び出し数、変換の CPU 上限、確保するメモリ。**大きく入力しても実際に使えるメモリで頭打ちになります**。

### 完了通知

ジョブの終了時（成功でも失敗でも）にこちらから通知します。メッセージには**ツール名、ファイル名、状態のみを含み、ファイルの内容は含みません**。

- **サイト内通知** —— サイドバーの通知ボタンに未読数と最近完了したジョブを表示します。認証が無効でも同じように使えます。
- **Email** —— HTML 版の通知メールで、サイトのロゴとツールのアイコンを含みます（画像はメールに埋め込むため、外部への接続は不要です）。プレーンテキスト版も添えます。宛先はアカウントのメールアドレス欄から取得し、LDAP / AD / SSO のアカウントは提供元から自動で同期します（属性を指定できます。例：`mail` / `mailPrimaryAddress`）。ローカルアカウントは個人カードで自分で変更できます。
- **メッセージアプリ / Webhook** —— Telegram、Slack、Microsoft Teams、Discord、Zulip、Nextcloud Talk、LINE、汎用 Webhook。**これらのチャネルは現時点では開発段階と記載しています**：ペイロードの形式には単体テストがありますが、実際のサービスとのエンドツーエンドの検証はまだ行っていません。実機で送信し、受信者が受け取りを確認できているのは Email だけです。
- **1 人ずつ選べます** —— どのチャネルを有効にするかは各ユーザーが決めます。管理者は接続設定（SMTP、Bot token など）の入力を担当します。

管理者は「設定 → 通知設定」と「設定 → バックグラウンドジョブと並列度」で調整でき、「設定 → ジョブ管理」でサイト全体のジョブを確認できます。

## AD / LDAP ディレクトリ管理

接続できるのは出発点にすぎません —— 実際に問題になるのは、主要 DC の再起動、権限を主要グループに付けたのに反映されない、退職した人がシステムに残っている、アカウントが他人に使われる、といった点です。

- **複数のドメインコントローラーによる冗長化** —— サーバーのアドレスは複数台入力でき（カンマまたは改行区切り）、順に試します。主要 DC のメンテナンスや再起動のときは自動で次の 1 台に切り替わるため、全社員がログインできなくなることはありません。接続にも照会にもタイムアウトがあり、DC につながらないときは数秒以内に明確なメッセージを返すため、ユーザーが待たされ続けることもありません。停止していた DC は復旧すると自動的にローテーションに戻ります。
- **AD の主要グループ（primaryGroupID）も有効** —— AD の主要グループは **`memberOf` に現れません**：あるグループを主要グループに設定して権限を付けると、メンバーが誰も権限を受け取れず、しかも AD ユーザーの「所属するグループ」タブでも原因がわかりません。現在は権限の解決にあわせて含めます。OpenLDAP にはこの概念がないため、動作は変わりません。
- **入れ子のグループも継承します** —— 上位の部署グループに権限を割り当てると、サブグループのメンバーも受け取れます（グループのツリーはもともと画面に表示されているのに継承しないのでは、非対応と明記するよりも誤解を招きます）。
- **退職 / 無効化されたアカウントが見えます** —— ユーザー一覧に「ディレクトリに存在しません」と「AD 側で無効」の 2 つのビューとバッジを追加しました。判定は**完全スキャンのみ**を根拠とします：名称の絞り込み付きの同期ではディレクトリの一部しか見えず、それを基準にすると組織全体を退職扱いにしてしまうため、完全スキャンをしていないときは結論を出しません。ローカルと SSO のアカウントには決して印を付けません。
- **パスワードの期限切れの予告** —— あと何日で期限切れかを表示します（期限切れは別途表示）。日付は AD 自身が計算した値を読むため、細かなパスワードポリシー（PSO）や「パスワードを無期限にする」が適用されている人でも正確です —— ドメインの全体設定から自分で推定すると誤った値になります。
- **一括での無効化と、その安全弁** —— ビュー内のアカウントをワンクリックで無効化でき、押す前に試算して実際に何人に影響するかを表示します。同期後に自動で無効化する設定もできます（**既定は無効**）。**一度に変更する人数がディレクトリのアカウント総数の 20% を超えると、バッチ全体を中止し、1 人も変更しません** —— サービスアカウントのパスワード期限切れや検索範囲の変更で「全社員が消えた」ように見えることがあり、そのときは何もしないのが正解だからです。無効化するだけで削除はせず、アカウントも権限の割り当ても残します。組み込み管理者には決して手を付けません。
- **今、誰がログインしているか** —— ユーザー一覧にオンライン人数を表示します（同じ人がブラウザーを複数開いていても 1 人と数えます）。アカウントごとに現在のログイン端末（ブラウザー / OS、送信元アドレス、最終アクティビティ）を確認でき、個別または一括で強制ログアウトできます。操作は監査記録に残ります。アカウント漏えいが疑われるときは、パスワードを変更しなくてもまずすべての端末を切断できます。
- **権限の割り当てに、相手のログインを待つ必要はありません** —— ディレクトリの参照からどのユーザーをクリックしてもそのままロールを割り当てられるため、新入社員は初日から使えます。「所属グループ」の各行からも、その場でグループ権限を設定できます。従来は OU 全体にしか割り当てられませんでした。
- **「結局この人は何が使えるのか」が一目でわかります** —— ユーザーの編集時に「実効権限」パネルを開くと、最終的にどのツールを使えるのか、どの項目がどのルール由来か（直接のロール / 入れ子を含むグループ / OU）まで表示します。監査への回答や引き継ぎの説明にそのまま使えます。

## LLM AI 付加機能（任意。既定は無効）

OpenAI 互換のバックエンド（ローカルの Ollama、LiteLLM などの LLM ゲートウェイ、vLLM、LM Studio、DGX Spark）を接続すると、**14 個のツール**に自動でスマートな機能が加わります：

| ツール | LLM が何をするか | モード |
|---|---|---|
| 一文ずつ翻訳 | 翻訳時にレイアウトを保持 + 分野の専門用語 | text |
| 文書の翻訳 | オフィス文書全体を別の言語に翻訳し、同じ形式・同じレイアウトのファイルを出力 | text |
| テキスト抽出 | PDF の 2 段組で切れた文をつなぎ直す | text |
| OCR 文字認識 | OCR の typo を補正（word count が同じときのみ適用し、ハルシネーションによる書き換えを防ぎます） | text |
| フォームの自動入力 | 入力後、LLM が PNG を見て項目のずれ / 見切れを検証 | **vision** |
| 送付前チェック | 内容の意味チェック + PNG のビジュアル検証（正規表現 / 構造チェックで拾えない問題を補います） | text + **vision** |
| 文書の匿名化 | 正規表現で拾えない顧客コード / 上司の氏名 / 社内番号 | text |
| テキストの匿名化 | 上と同じ。プレーンテキスト入力版 | text |
| 文字数の集計 | 3-5 文の要約 + TOP 10 キーワードを追加で生成 | text |
| 会議の要約 | 文字起こし → 要約 / 決定事項 / タスク / リスク / 章立て。各項目に発言番号が付き、あとから確認できます | text |
| 公文書の起案 | 平易な用件 → 簽（主旨・說明・擬辦）や函、来文 → 簽辦意見、段落の書き直し、案件履歴。公文ナレッジベースを参照可能。書式はプログラムが組み立て、事実はプログラムが照合 | text |
| 注釈の整理 | 複数のレビューコメントを「重大 / 一般 / 質問」に自動で仕分け | text |
| 文書の差分比較 | 行 diff に加えて「主にどの条項が変わったか」の自然言語の要約 | text |
| 電子請求書の処理 | ルールで対応できない品目の勘定科目を LLM で判定 | text |

**中核のツールは LLM にまったく依存しません**。設定しなくても、これまでどおりすべて使えます。詳しくは **[LLM.md](LLM.md)** をご覧ください。

## 音声サービス連携（任意、既定では無効）

**会議の録音**を、そのまま使える議事録に変換します。しかも**重要な録音がネットワークの外へ出ることはありません**。

録音は **[JTLW](https://jasoncheng7115.github.io/jt-live-whisper/)**（jt-live-whisper、
社内ネットワークに自前で立てられます）へ渡して認識と発言者分離を行います。**要約・決定事項・タスク・マインドマップ・翻訳はすべて本システムに残ります**。

### 使い方

1. 管理画面 →「音声サービス（JTLW）」で送信先アドレスと API キーを入力します（自己署名証明書の場合は証明書を貼り付けるだけです。
   **検証は無効にしないでください**）。設定が済むまで「会議録音の文字起こし」はグレーアウトのままです。
2. 録音・録画をアップロードし、変換後は**ワンクリックで「会議要約」へ渡します**。
3. API 経由でも利用できます：`POST /tools/meeting-transcribe/api/meeting-transcribe`。

### 効果

| | |
|---|---|
| 速度 | 28.3 分の会議で約 **112 秒**（実時間の 15 倍速、実測） |
| 文字起こし | **タイムスタンプと発言者**付きで、聞きながら読めます。波形をクリックすればその位置から再生され、再生中の行がハイライトされます |
| 発言者 | 記号をクリックして名前に変更できます。既定では同じ発言者の行がまとめて変わります |
| 精度 | 公開コーパス（AISHELL-4）の正解データで測定：**パイプライン全体と音声サービス自身が測定した数値の差は 0.12 ポイント** |

### なぜこの分担なのか

- **音声はネットワーク内に留まります。** JTLW は自前で立てるため、録音をクラウドサービスへ送る必要はありません。
- **録音ファイルは短時間有効な署名付き URL で受け渡します。** アカウントや資格情報を相手に渡す必要はなく、期限が来れば自動的に失効します。
- **要約と決定事項は本システムに残り**、他の 13 個の LLM 支援ツールと同じ設定と監査記録を使います。
- **引用はテキストではなく発言箇所の番号に紐づきます。** 校正のやり直しや用語集の更新のあとも、すでに作成された決定事項やタスクは
  同じ音声箇所を指し続けます。

設定しなければ従来どおりで、**他の 50 個のツールにはまったく影響しません**。

## プライバシー / セキュリティの要点

- **⚠ 「公衆インターネット」への直接公開はおすすめしません** —— 社員はこのツールで会社の**社内 / 機密文書**（契約書、見積書、個人情報、統一番号データなど）を扱うことが多くあります。インターネットに公開すると誰でもログインやファイルのアップロードを試せるため、アカウントや URL が漏れれば**情報漏えいのリスク**があります。社内ネットワークなら接続できるのは社員だけで、しかも先にログインが必要です。**社内ネットワーク / VPN でのみ使用してください**。業務上どうしても外部公開が必要な場合は「リスクは自己責任」となり、少なくともリバースプロキシ、HTTPS、認証、二要素認証の必須化、WAF またはレート制限を導入し、依存パッケージを継続的に更新してください。詳しくは [OPS.md](OPS.md) をご覧ください。
- **⚠ ローカル以外からのアクセスは必ずリバースプロキシ + HTTPS 経由で** —— 「ローカルで 1 人だけ」以外の使い方（複数人、社内の他のコンピューター、外部）では、**必ず nginx（または Caddy）のリバースプロキシ + HTTPS の後ろに置き、`:8765` をネットワークに直接公開しないでください**。アプリは既定で `127.0.0.1:8765`（HTTP のみ、TLS なし）にしかバインドしないため、直接公開するとパスワードや文書が平文で送られます。正しい設定は以下と [OPS.md](OPS.md) をご覧ください。
- **クラウドに出さず、データは自分の手元に残ります** —— ファイルの処理はすべてあなたのサーバー上で行われます
- **データディレクトリが独立しています** —— ユーザーの個人ファイルと混ざらず、Windows でも roam しません
- **既定では認証は無効です**（スタンドアロンモード） —— 新規インストールではこれまでどおり誰でもそのまま使えます。複数人や社内ネットワークへの配置のときに有効にしてください
- **監査記録 + SIEM 転送** —— 認証を有効にすると、機微な操作をすべて記録し、リアルタイムに転送できます
- **任意の LLM 検証** —— 既定は無効です。自分で Ollama / ローカルの LLM を接続したときにだけ有効になり、クラウドには送りません

### リバースプロキシ（nginx）のセキュリティ設定

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name docs.example.com;

    ssl_certificate     /etc/letsencrypt/live/docs.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/docs.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    server_tokens off;            # 不洩 nginx 版本（ZAP「Server Leaks Version」）
    client_max_body_size 300M;    # 必設：上傳大檔
    proxy_read_timeout 900s;      # 必設：LLM 工具單筆推理可能數分鐘
    proxy_send_timeout 900s;
    proxy_buffering off;

    location / {
        proxy_pass http://127.0.0.1:8765/;          # 後端只聽 127.0.0.1
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;  # 必設：後端據此設 Secure cookie + HSTS
    }
}
```

セキュリティヘッダー（CSP / HSTS / X-Frame-Options / X-Content-Type-Options / Referrer-Policy）は
**バックエンドのアプリが自動で設定します**（HSTS は `X-Forwarded-Proto` で https を判定します）→ **nginx 側でもう一度
`add_header` しないでください**。ヘッダーが重複します。よくある落とし穴 3 つ(必ず root パスに置く、`client_max_body_size`、
タイムアウト)、7 項目の共通要件、`X-Forwarded-For` の偽造対策、そして **nginx / Caddy / Apache / HAProxy /
Traefik / IIS(ARR) / F5 BIG-IP** の完全な例は、すべて [OPS.md](OPS.md) をご覧ください。

詳しくは [SECURITY.md](SECURITY.md) をご覧ください。
